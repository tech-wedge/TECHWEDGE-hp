# TechWedge HP

3人のAI自動化チーム（悠太・かげ・三富）のコーポレートサイト。静的HTML＋最小JS・フレームワークなし。

> **設計の正本**: vault `業務効率化PJ/HP設計_TechWedge_2026-07.md`（コンセプト・確定事項・サイトマップ台帳・残作業の実行書）。**コードを触る前に必ず正本§1（確定事項）と§11（実行書）を読むこと。**

## 起動

- そのままブラウザで `index.html` を開けば動く（ビルド不要）
- サーバー経由: `.claude/launch.json` の `techlore-hp`（port 3008）／手動なら `npx serve -p 3008 .`

## 編集ルール（壊すと悠太チェックで差し戻しになるやつ）

1. **組織名の変更**: `assets/site.js` 冒頭の `BRAND_HEAD` / `BRAND_TAIL` / `BRAND_PROVISIONAL` だけ。HTMLに直書きしない
2. **カラー変更**: `tokens.css` のみ。緑(#2EA043)は「CTA・実測数字・基準線」限定＝装飾に使わない。純黒(#000)禁止
3. **⚠ 助成金の表現は変更禁止級**: 「対象となる場合があります」「要件・審査あり」「支給を保証するものではありません」「適用時の目安」をセットで維持。**断定表現（「国が出します」「必ず戻る」等）は景表法リスクで悠太NG済み**（2026-07-06裁定）
4. **確定コピー**: タグライン「現場を動かす人に、テクノロジーを。」／「自動化できないものは『できない』と言います」／フッター「このサイトも、私たちのAIワークフローで制作しました。」は変更禁止
5. **数字は一次ソースから**: 実測値の確定形は「170min→20min（≒3時間→20分）」「約88%（具体的な統計表記）」「約9割（メンバー紹介文等の語り文脈での表記、社長裁定2026-07-16）」「400件」。出典は vault `業務効率化PJ/建設業向け/営業資料/領収書仕分け_BeforeAfter.md`。新しい数字を足すときは必ず出典確認。**ダミー数字・盛り禁止**。**「88%と9割で表記がズレてる」は不具合ではなく意図的な使い分け**——統計面と語り文脈で表記を統一しようとしない
6. **禁止コピー**: 詩的表現・楽屋裏説明・想像のFAQ・競合実名・営業戦略の内部図解
   - **★6-b. 読み手を「能力の欠如」で名指しせん（2026-08-20悠太指摘「バカにしてるみたいで俺はきらいやな」）**: `AIが苦手な建設会社へ` はNG。★**読み手は「苦手な人」やなく「****興味はあるけど、いまいち分からん人****」や。**——**関心はある側の人間として書く。**
     - ❌ 苦手／わからない方／初心者／詳しくない方 ＝**相手を分類しとる**
     - ⭕ **相手が実際に言う言葉をそのまま使う**（例: 「AIって、実際なにができるの？」）。★**原本のDMが「メーカーの職人が忙しくて施工してもらえない…」でやっとる手口や**（`myshia（内装金物）/営業/DM原本テンプレート_参考.md`＝2025年7月に806社送って反響率が高かった実物）
     - ⚠**お客さん側の言葉として括弧に入っとる場合は別**（`「ITは苦手」の壁` 型）。**見出しで名指しするのがアカン**
   - **★6-c. 「職人であること」を押す（2026-08-20悠太指示）**: ★**中芝は実際に現場に出とる内装金物の施工会社や。**——**建設業がDX業者に持つ定番の反論「****IT屋はうちの仕事わかってへん****」を正面から潰せる、****外部のIT企業には真似でけん札****や。**事実として小さく書くやなく、**訴求として使う**。**「経営する」やなく「施工をしている」**（経営者の話に聞こえると職人の手触りが消える）
7. **⚠ 価格は一切表示しない（2026-07-10悠太指示・2026-07-16再確認）**: 全ページの価格欄は「料金はお問い合わせください」で統一。金額を出す商談スタイルから無料相談で案内する方式へ意図的に変更した経緯があり、**「価格が書いてない」は不具合ではない**。QA・レビューで価格未記載を指摘されても、このルールを優先して価格を書き足さないこと（2026-07-16、QAで一度誤って価格を復活させ悠太指摘で再修正した事故あり）
   - **★7-b. このルールは「HPのページ」やなくTechWedge名義の対外露出物すべてに及ぶ（2026-08-19・代行裁定）**: **チラシ・DM文面・提案書・SNS・LP** も同じ。★**根拠は悠太の決定の理由や**——「**金額を出す商談スタイルから無料相談で案内する方式へ意図的に変更した**」のは**商談の型の変更**であって、ページの体裁の話やない。**チラシはまさに「無料相談へ誘導する道具」やから、****媒体が変わっても理由がそのまま効く。**
   - **★7-c. 例外＝助成金の「割合」だけは書いてよい**（2026-07-16据え置き判定）: **「最大75%」等の****公的制度の割合表示は自社の価格やない****から可**。ただし**ルール3の但し書き（「対象となる場合があります」「要件・審査あり」等）は必ずセット**。
   - 🚨**7-d. 「実質◯万円」は書いたらアカン**: **助成金適用後の金額は、****割り戻したら定価が出る****＝実質的な価格表示や。**（例: 「実質12.5万円」→ 75%助成なら定価50万と分かる）。**割合はOK・金額はNG**の線引きを守れ。
8. **⚠ CTA見出しの演出調禁止（2026-07-11悠太指摘・全5ページ修正済み）**: 「A、[改行/句点]B。」という"溜めてから決め台詞"の2段階構成（コンマ・改行＋断定的な決め台詞）はNG。単純な名詞ラベルや短い区切りフレーズ（「あなたの業種から。」等）はこの限りでない。太字強調＋em-dash＋命令形を組み合わせた煽り構造の一文も同様にNG（2026-07-16修正実績あり）
9. **⚠ nav/footer（ヘッダー・フッターのリンク一覧）は全ページにベタ書き・共通パーツ化なし**（2026-08-19判明・事故再発防止）。nav構成を変える改修（項目名変更・追加・削除）をしたら、**変更後に必ず旧文言の残存を機械確認する**: `grep -l '<旧nav項目名>' *.html`（例: `grep -l '建設業の方へ' *.html`）で該当ファイルが0件になるまで直す。**ヘッダーだけ更新してフッターを忘れる事故が実際に発生した**（commit 21b792eでコラム記事6本のフッターが取り残され、本番でヘッダー/フッター不一致のまま数時間公開された）。共通パーツ化（include/ビルド時差し込み）は本質的な解決策だが、かげの実装領域との調整が必要なため提案止まり・現状は着手しない

## 新ページの追加レシピ

1. `company.html` をコピーしてリネーム（最小構成のため雛形に最適）
2. `<title>`・`<meta description>`・ヒーロー・本文セクションを書き換え（セクションは `sec-head` の連番を維持）
3. ナビの `class="now"` を自ページに付け替え、**全ページのnav/footerに新ページへのリンクを追加**（編集ルール9のgrep確認を必ず実施）
4. 追加してよいページは正本§7の台帳にあるものだけ。**解禁トリガーが満ちてないページは作らない**
5. 公開前に正本§11のQAチェックを通す
